# agents.md

Руководство для ИИ-агентов, работающих с этим проектом.

## Обязательные правила

1. **Информационная база.** Конфигурация связана с файловой информационной базой
   `File="C:\Users\psi\Downloads\AICourse\DBIS06_BSP";`
   Пользователь: `Администратор`, пароль пустой.
2. **Разработка только в расширениях.** Вся разработка ведется в новых расширениях конфигурации.
   Каждое расширение складывается (выгружается в XML) в каталог `Extensions\<ИмяРасширения>`.
3. **Основную конфигурацию не меняем.** Каталог `Config` и основная конфигурация базы
   только для чтения: не редактировать файлы в `Config`, не выполнять `/LoadCfg`,
   `/LoadConfigFromFiles` и `/UpdateDBCfg` для основной конфигурации.
4. **Буква «е» вместо «ё».** В именах, синонимах и комментариях метаданных используем `е`,
   а не `ё` (например, `Отчет`, `Расчет`, `Счет`, а не `Отчёт`, `Расчёт`, `Счёт`).
5. **Тестирование — Vanessa Automation** из `C:\Users\psi\Vanessa` (см. раздел ниже).

## Структура проекта

| Путь | Назначение |
| --- | --- |
| `Config\` | Выгрузка основной конфигурации в XML (иерархический формат, `ConfigDumpInfo.xml`, формат выгрузки 2.21). Только чтение. |
| `Extensions\` | Расширения конфигурации, разрабатываемые в проекте (по подкаталогу на расширение). |
| `.v8-project.json` | Настройки для навыков 1С (`cc-1c-skills` в `~\.claude\skills`): платформа, база `bsp`, `configSrc` = `Config`. |

## Навыки 1С (cc-1c-skills)

- Навыки читают `.v8-project.json`; база по умолчанию — `bsp` (файловая `DBIS06_BSP`).
- Новое расширение создавать навыком `/cfe-init` с `-OutputDir "Extensions\<Имя>"` и
  `-ConfigPath "Config"` (по умолчанию навык кладет в `src\cfe`, здесь так нельзя).
  После создания добавить расширение в `databases[0].extensions` файла `.v8-project.json`:
  `{ "name": "<Имя>", "src": "Extensions\\<Имя>" }`.
- Заимствование и перехват: `/cfe-borrow`, `/cfe-patch-method`; проверка: `/cfe-validate`.
- Загрузка расширения в базу — навыки `db-*` (`/db-load-xml`, `/db-update`, `/db-cfe-admin`)
  только с указанием расширения; навыки `meta-*`, `cf-*`, `form-*` и т.п. не применять
  к каталогу `Config` (`editingAllowedCheck: deny` дополнительно защищает объекты на поддержке).

## Разработка расширений

- Создавать новое расширение под задачу, не трогая основную конфигурацию. Назначение — «Адаптация»
  (или «Дополнение» — по смыслу), с собственным префиксом имен (свойство `NamePrefix`, например `рсш_`).
- Заимствовать в расширение только нужные объекты; поведение менять через аннотации
  `&Перед`, `&После`, `&Вместо`, `&ИзменениеИКонтроль`.
- Следовать стандартам разработки 1С и механизмам БСП: переопределяемые модули
  (`*Переопределяемый`), `ОбщегоНазначения`, подключаемые команды, функциональные опции и т.д.
- Выгрузка расширения из базы в XML:

  ```powershell
  & "C:\Program Files\1cv8\8.5.1.1529\bin\1cv8.exe" DESIGNER /F"C:\Users\psi\Downloads\AICourse\DBIS06_BSP" /N"Администратор" /P"" /DisableStartupDialogs `
      /DumpConfigToFiles "C:\Users\psi\aiwsis06\bsp\Extensions\<ИмяРасширения>" -Extension <ИмяРасширения> /Out dump.log
  ```

- Загрузка расширения из XML в базу и применение:

  ```powershell
  & "C:\Program Files\1cv8\8.5.1.1529\bin\1cv8.exe" DESIGNER /F"C:\Users\psi\Downloads\AICourse\DBIS06_BSP" /N"Администратор" /P"" /DisableStartupDialogs `
      /LoadConfigFromFiles "C:\Users\psi\aiwsis06\bsp\Extensions\<ИмяРасширения>" -Extension <ИмяРасширения> /UpdateDBCfg /Out load.log
  ```

- Проверка: `/CheckModules -ThinClient -Server -Extension <ИмяРасширения>` или
  `/CheckConfig -Extension <ИмяРасширения>`. Результат читать из файла `/Out`.
- Пакетный режим конфигуратора требует, чтобы база не была открыта в монопольном режиме
  (закрыть открытые сеансы конфигуратора).

## Тестирование (Vanessa Automation)

Каталог `C:\Users\psi\Vanessa` (подробности — в его `README.md`):

- `tools\vanessa-automation-single.epf` — обработка VA 1.2.043.42;
- `tools\VAExtension.1.32.cfe` — расширение VA (должно быть загружено в базу);
- `va.ps1` — раннер сценариев; `install\Загрузить-VAExtension.ps1` — установка VAExtension;
- `features\` — сценарии (`features\smoke\bsp-demo-smoke.feature` — дымовой пример).

Скрипты по умолчанию настроены на серверную базу `localhost\bsp_demo` — для этого проекта
всегда передавать файловую базу параметром `-InfoBasePath`.

Установка VAExtension в базу (один раз; это служебное тестовое расширение, основная
конфигурация не меняется):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\Users\psi\Vanessa\install\Загрузить-VAExtension.ps1 `
    -InfoBasePath 'C:\Users\psi\Downloads\AICourse\DBIS06_BSP' -User 'Администратор'
```

Запуск сценария:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\Users\psi\Vanessa\va.ps1 `
    -InfoBasePath 'C:\Users\psi\Downloads\AICourse\DBIS06_BSP' -User 'Администратор' `
    -Feature <путь к .feature>
```

- Сценарии для доработок класть рядом с расширением: `Extensions\<ИмяРасширения>\features\*.feature`
  (язык `# language: ru`, подключение `Дано я подключаю TestClient "Демо" логин "Администратор" пароль ""`).
- Результат — каталог `C:\Users\psi\Vanessa\reports\run-<дата-время>` (`junit.xml`, `status.txt`,
  `steps.log`, снимки ошибок). Успех: статус `0`, число сценариев больше нуля и нет
  `failure/error/skipped`. Код выхода процесса сам по себе успехом не считается.
