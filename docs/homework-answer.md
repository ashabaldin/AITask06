# Домашнее задание, урок 6: интеграция «Счет на оплату БСП → Заказ УФ»

Репозиторий: https://github.com/ashabaldin/AITask06

## Что сделано

Обмен из `_ДемоСчетНаОплатуПокупателю` (демо БСП 3.1.5) в `Заказ` (Демонстрационное приложение 1.0.41)
через JSON-файл, с ручным запуском с обеих сторон. Все доработки — в двух новых расширениях,
основные конфигурации и существующие модули не менялись.

| Расширение | ИБ | Что делает |
|---|---|---|
| `ОбменСчетами` (`осч_`) | БСП | Обработка «Выгрузка счетов в УФ»: период, организация, файл → JSON (шапка + товары: номенклатура, количество, цена, сумма). |
| `ЗагрузкаСчетовБСП` (`зсб_`) | УФ | Обработка «Загрузка счетов из БСП» с протоколом; регистр «Соответствия объектов БСП»; сопоставление существующих организаций, покупателей, валют и товаров; заказы без дублей и без проведения. |

Соответствие ТЗ:

1. Обмен через файлы, ручной запуск — обработки в обеих ИБ.
2. Минимальная шапка (номер, дата, организация, покупатель, валюта, сумма) и товары (номенклатура, количество, цена, сумма).
3. Справочники не создаются и не передаются — только ключи для поиска существующих (UUID, наименование, артикул, код валюты).
   Найденное запоминается в регистре соответствий, ненайденное показывается в протоколе и задается вручную в форме регистра.
4. Повторный обмен находит заказ по UUID счета и обновляет его; дублей нет; заказы записываются без проведения.
5. Сверка: по решению заказчика отчет сверки отложен; наличие заказов, реквизиты шапки и товарные строки
   проверяются автоматическим тестом `uf/Extensions/ЗагрузкаСчетовБСП/tests/e2e-proverka.bsl`.
6. Проверены обмен, повторная загрузка и сверка данных — см. «Проверка».

## Проблемы и решения

1. **Справочники двух баз не связаны.** В УФ нет ИНН, коды валют — автономер, по наименованию совпала только EUR.
   Решение: регистр соответствий UUID БСП → ссылка УФ с автоподбором (артикул, наименование) и ручным
   заполнением; неоднозначность не выбирается наугад, а попадает в протокол.
2. **Стартовое окно БСП «Информационная база была перемещена»** блокировало Vanessa. Решение: программный
   аналог кнопки «Это копия» — внешние ресурсы остаются запрещены.
3. **Код в шагах Vanessa выполняется в безопасном режиме** — запись тестового файла падала.
   Решение: статичный тестовый JSON в `features/fixtures/`.
4. **Скриншоты Vanessa получались полосками 10 px** (снималось служебное окно). Решение: перед снимком
   активировать окно клиента шагами «получаю данные процесса по заголовку окна» и «активизирую процесс».
5. **Противоречие в дизайне:** «выгружать непомеченные счета» против признака удаления в формате.
   Решение: выгружаются все счета; помеченный счет помечает существующий заказ, иначе пропускается с протоколом.
6. **Разные режимы совместимости:** в БСП 8.3.14 нет `Асинх`/`Ждать` — клиентский код на `ОписаниеОповещения`;
   в УФ синхронные вызовы запрещены — код на `Асинх`/`Ждать`.
7. **Окружение Windows:** PowerShell 5.1 читает скрипты без BOM как ANSI, Git Bash искажает кириллические
   аргументы `1cv8.exe`, `СтрШаблон` падает на лишних параметрах, язык запросов не поддерживает подзапросы
   в списке полей. Решение: файлы с BOM, запуск конфигуратора из PowerShell, исправления по месту.
8. **Выгрузки конфигураций огромные и не должны попасть в удаленный репозиторий.** Решение: `bsp/Config` и
   `uf/Config` в `.gitignore` с первого коммита, `.gitattributes` хранит файлы 1С байт-в-байт.
