# Обмен «Счет на оплату (БСП) → Заказ (УФ)» через файлы — дизайн

Дата: 2026-11-06. Источник требований: ТЗ урока 6 (`C:\Users\psi\Downloads\AICourse\task06\ДЗ Урок 6.pdf`).

## Зачем

Две несвязанные ИБ: демо БСП (`DBIS06_BSP`) и демо УФ (`DBIS06_UF`). Нужно по ручной команде
переносить счета покупателям из БСП в заказы УФ, не создавая справочников и без дублей при повторах.
Результат — домашнее задание: работающая интеграция, проверка Vanessa, иерархия AGENTS.md.

## Цели

1. Выгрузка `Документ._ДемоСчетНаОплатуПокупателю` из БСП в JSON-файл по ручной команде.
2. Загрузка файла в УФ по ручной команде в `Документ.Заказ`.
3. Передаются: шапка (UUID, номер, дата, организация, покупатель, валюта) и товары
   (номенклатура, количество, цена, сумма).
4. Используются существующие товары, контрагенты, организации, валюты УФ; их доп. реквизиты не передаются.
5. Повторная загрузка обновляет тот же заказ (без дублей). Заказы только записываются, не проводятся.
6. Проверка Vanessa: первичная загрузка, повторная загрузка (нет дублей, изменения применены).

## Не цели (на этом этапе)

- **Отчет сверки — отложен по решению пользователя.** Дизайн оставляет для него опору: файл
  выгрузки содержит полный снимок счетов, регистр соответствий связывает UUID счета с заказом.
- Kafka и существующая сверка товаров из вебинара — не используются.
- Создание/обновление справочников в УФ, передача их доп. реквизитов.
- Обратный обмен, автоматический (регламентный) запуск, удаление заказов при удалении счета.

## Анти-цели

- Правка основных конфигураций или существующих модулей (только новые расширения).
- Дубли заказов при повторной загрузке.
- Молчаливая потеря данных: незагруженный счет без объяснения причины.

## Ограничения

- Только новые расширения: `bsp/Extensions/<Имя>`, `uf/Extensions/<Имя>`; основные `Config` — только чтение.
- УФ: режим совместимости 8.3.27, синхронные вызовы и модальность запрещены (асинхронный клиентский код);
  БСП-модулей в УФ нет. БСП: совместимость 8.3.14, можно использовать `ОбщегоНазначения` и т. п.
- Буква «е» вместо «ё» в метаданных. SOLID / DRY / KISS. Внешние источники — ссылками в комментариях.
- Справочники не связаны: в УФ нет ИНН; код валюты в УФ — автономер, не ОКВ.

## Подходы к сопоставлению справочников (выбран 2)

1. Только по наименованию — просто, но любое расхождение имен блокирует обмен без способа починки.
2. **Выбран.** Регистр соответствий с автоподбором: ищем по ключу, найденное запоминаем по UUID объекта БСП;
   ненайденное видно в протоколе и задается вручную один раз в форме регистра. Устойчиво к переименованиям.
3. Ручная таблица без автоподбора — надежно, но лишняя ручная работа.

## Решение

### Расширение БСП `ОбменСчетами` (префикс `осч_`)

- Общий модуль `осч_ВыгрузкаСчетов` (сервер): `ВыгрузитьВJSON(ДатаНачала, ДатаОкончания, Организация) → Строка`.
  Отбор: непомеченные на удаление счета за период (организация — необязательный отбор).
  Формирует структуру формата (ниже) и сериализует `ЗаписьJSON`.
- Обработка `осч_ВыгрузкаСчетовВУФ` с формой: период, организация, кнопка «Выгрузить» — получает
  строку с сервера и сохраняет файл через `ПолучитьФайл`/диалог (клиент). Подключается в раздел
  демо-продаж (подсистема) через командный интерфейс.
- Роль `осч_ВыгрузкаСчетов` — использование обработки.

### Формат файла (JSON, UTF-8)

```json
{"format":"bsp-invoices","version":1,"createdAt":"2026-11-06T12:00:00",
 "invoices":[{"id":"<UUID счета>","number":"...","date":"2026-11-01T10:00:00","deleted":false,
   "organization":{"id":"<UUID>","name":"..."},
   "customer":{"id":"<UUID>","name":"..."},
   "currency":{"id":"<UUID>","code":"643","name":"руб."},
   "amount":1000.00,
   "goods":[{"lineNo":1,"item":{"id":"<UUID>","name":"...","article":"..."},
             "quantity":2,"price":500.00,"sum":1000.00}]}]}
```

`sum` — `Сумма` строки счета (то, что пойдет в `Заказ.Товары.Сумма`). Справочники несут только ключи
сопоставления (UUID + наименование, артикул, код валюты), а не доп. реквизиты.

### Расширение УФ `ЗагрузкаСчетовБСП` (префикс `зсб_`)

- Регистр сведений `зсб_СоответствияОбъектовБСП` (непериодический): измерения `ТипОбъекта` (строка 50:
  `Организация`, `Контрагент`, `Валюта`, `Номенклатура`, `СчетНаОплату`), `ИдентификаторБСП` (строка 36);
  ресурс `Ссылка` (составной: Организации, Контрагенты, Валюты, Товары, Документ.Заказ);
  реквизит `Представление` (строка — наименование/номер из БСП, для ручного сопоставления).
- Общий модуль `зсб_СопоставлениеОбъектов` (сервер): `НайтиСсылку(ТипОбъекта, ДанныеОбъекта) → Ссылка | Неопределено`.
  Порядок: регистр по UUID → автоподбор → при единственном найденном записывает соответствие.
  Автоподбор: организация, контрагент, валюта — точное наименование (коды валют в УФ — автономер,
  поэтому код ОКВ не используется; расхождения вроде «руб.»/«Рубль» задаются вручную в регистре);
  товар — артикул, затем наименование; учитываются только непомеченные элементы, не группы;
  несколько кандидатов = не найдено.
- Общий модуль `зсб_ЗагрузкаСчетов` (сервер): `ЗагрузитьИзJSON(Текст) → протокол (массив строк/структур)`.
  Для каждого счета в своей транзакции: сопоставить все ссылки; если что-то не найдено — счет пропускается,
  в протокол пишется что именно; иначе найти заказ по регистру (`СчетНаОплату`) или создать новый,
  перезаполнить шапку и товары, `Записать(РежимЗаписиДокумента.Запись)`, сохранить соответствие.
  Счета с `deleted=true` — заказ помечается на удаление, если существует (KISS, без удаления).
  Проверка формата/версии файла до загрузки.
- Обработка `зсб_ЗагрузкаСчетовБСП` с формой: выбор файла (асинхронно, `ПоместитьФайлНаСерверАсинх`),
  кнопка «Загрузить», поле протокола. Команда — в подсистеме «Продажи» через командный интерфейс.
- Роль `зсб_ЗагрузкаСчетов` — обработка, регистр, чтение справочников, запись заказов.

### Заполнение заказа

| Заказ | Откуда |
|---|---|
| Дата | дата счета |
| Номер | автонумерация УФ (номер БСП хранится в `Представление` регистра) |
| Организация, Покупатель, Валюта | сопоставление |
| ВидЦен | `Покупатель.ВидЦен` |
| Склад | при создании — первый склад с `НеИспользовать = Ложь`, непомеченный; при обновлении не меняется |
| СостояниеЗаказа | при создании `Открыт`; при обновлении не меняется |
| Товары | полная перезапись: Товар, Количество, Цена, Сумма из файла |
| Сумма | итог по товарам (делает типовой `ПередЗаписью`) |

## Проверка

- `cfe-validate` и `/CheckModules -Extension` для обоих расширений; загрузка только с `-Extension`.
- Vanessa (`uf/Extensions/ЗагрузкаСчетовБСП/features`, `bsp/Extensions/ОбменСчетами/features`):
  выгрузка файла в БСП; загрузка в УФ → заказы созданы, не проведены; повторная загрузка → число заказов
  не изменилось; измененный счет → заказ обновлен; несопоставленный товар → понятная строка протокола.
