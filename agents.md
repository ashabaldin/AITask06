# Правила для агентов: проект интеграции двух ИБ 1С:Предприятие

Конфигурации информационных баз лежат в подкаталогах проекта (`bsp/`, `uf/`).
В каждом подкаталоге может быть свой `agents.md` с дополнительными правилами для этой ИБ.

## Обязательные правила

1. **Существующие модули не меняем.** Все доработки делаем только в новых модулях.
   Если нужно встроиться в типовую логику, используем новые общие модули, новые объекты
   или расширения конфигурации (перехват методов), а не правку исходного кода.

2. **Код пишем по принципам SOLID, DRY и KISS.**
   - SOLID: у модуля и процедуры одна ответственность; зависимости — через программные интерфейсы, а не через детали реализации.
   - DRY: общая логика выносится в общие модули, без копирования кода.
   - KISS: выбираем самое простое решение, которое закрывает требование.

3. **Внешние источники указываем всегда.** Если используем информацию из интернета
   (документация, статьи, ИТС, форумы, репозитории), указываем ссылку на источник
   в ответе, а при переносе решения в код — в комментарии рядом с ним.

4. **Перед написанием кода прогоняем ТЗ через навыки superpowers.**
   Навыки установлены глобально в `~/.claude/skills/`
   (источник: https://github.com/obra/superpowers). Порядок работы:
   - `brainstorming` — разбор ТЗ, уточнение требований и проектирование решения;
   - `writing-plans` — пошаговый план реализации;
   - `executing-plans` / `subagent-driven-development` — реализация по плану;
   - `verification-before-completion` — проверка результата перед сдачей.
   Дизайн кладем в `docs/superpowers/specs/`, планы — в `docs/superpowers/plans/`.

5. **Работа в git.** Доработки ведем в отдельной ветке (`feature/<тема>`), коммиты — по задачам плана.
   Выгрузки `bsp/Config` и `uf/Config` в git не входят (`.gitignore`): они только для чтения
   и восстанавливаются из ИБ. `.gitattributes` хранит файлы 1С байт-в-байт (BOM, CRLF) — не менять.

## Интеграция «Счет на оплату БСП → Заказ УФ»

- Дизайн: `docs/superpowers/specs/2026-11-06-invoice-order-exchange-design.md`, план и решения — в `docs/superpowers/plans/`.
- Транспорт — JSON-файл, запуск вручную с обеих сторон. Формат `{"format":"bsp-invoices","version":1,"invoices":[...]}`:
  шапка (`id` = UUID счета, `number`, `date`, `deleted`, `organization`, `customer`, `currency`, `amount`) и
  `goods` (`lineNo`, `item`, `quantity`, `price`, `sum`). Справочники передаются только ключами
  сопоставления (`id`, `name`, у товара `article`, у валюты `code`). Меняешь формат — меняй `version`
  и обе стороны сразу.
- БСП выгружает (`bsp/Extensions/ОбменСчетами`), УФ загружает и сопоставляет (`uf/Extensions/ЗагрузкаСчетовБСП`).
  Ключ заказа — UUID счета в регистре УФ `зсб_СоответствияОбъектовБСП`; заказы только записываются, не проводятся.
- Справочники двух ИБ не связаны (в УФ нет ИНН, коды валют — автономер), автоматически совпадает
  только EUR — остальное задается вручную в регистре соответствий.
- Отчета сверки пока нет (отложен заказчиком); опора для него — файл выгрузки и регистр соответствий.

## Инструменты (`tools/`)

Скрипты PowerShell, запуск `powershell -NoProfile -ExecutionPolicy Bypass -File tools\<скрипт>.ps1 ...`;
параметр `-Base BSP|UF` выбирает ИБ. Файлы `.ps1` и `.bsl` сохраняем в UTF-8 **с BOM** —
Windows PowerShell 5.1 иначе читает кириллицу как ANSI.

| Скрипт | Что делает |
| --- | --- |
| `run-bsl.ps1 -Base -Code <файл.bsl>` | Выполняет BSL на сервере ИБ через тонкий клиент и `tools/bin/ЗапускBSL.epf`; код присваивает строку переменной `Результат`. |
| `test.ps1 -Base -Tests "a.bsl,b.bsl"` | Серверные тесты: каждый `.bsl` возвращает `OK` или текст ошибки; код выхода = число упавших. |
| `ext-load.ps1 -Base -Name <Расширение>` | Загружает расширение из XML (`-Extension`), применяет и делает `/CheckModules`. |
| `va-run.ps1 -Base -Feature <.feature>` | Прогон Vanessa с профилем ИБ и итог по `junit.xml`. |
| `e2e.ps1` | Сквозная проверка обмена: сброс заказов обмена → выгрузка БСП → соответствия → загрузка ×2 → проверка данных. |
| `runbsl/` | Исходники `ЗапускBSL.epf` (собирать навыком `epf-build`). |

## Известные особенности окружения

- **COM-коннектор `V85.COMConnector` не работает** (библиотека типов не зарегистрирована,
  регистрация требует прав администратора) — для доступа к данным используй `tools/run-bsl.ps1`.
- **Кириллические аргументы `1cv8.exe` передавай из PowerShell**, не из Git Bash: bash их искажает.
- **Код в шагах Vanessa «я выполняю код встроенного языка на сервере (Расширение)» работает в
  безопасном режиме**: файлы писать нельзя — тестовые файлы клади в `features/fixtures/`.
- **Скриншот Vanessa** (`И я сохраняю скриншот "..."`) иногда снимает служебное окно шириной 10 px.
  Перед ним активируй окно клиента: `И я получаю данные процесса по заголовку окна '<Начало заголовка>*'`,
  `И я активизирую процесс '$ProcessId$'`.
- Тесты, создающие данные, обязаны убирать за собой; проверяй, что после прогона в УФ остались
  исходные 20 заказов плюс заказы обмена.
