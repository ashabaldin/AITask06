# Правила для агентов: проект интеграции двух ИБ 1С:Предприятие

Конфигурации информационных баз лежат в подкаталогах проекта (`bsp/`, `uf/`).
В каждом подкаталоге может быть свой `agents.md` с дополнительными правилами для этой ИБ.

## Обязательные правила

1. **Существующие модули не меняем.** Все доработки делаем только в новых модулях.
   Если нужно встроиться в типовую логику, используем новые общие модули, новые объекты
   или расширения конфигурации (перехват методов), а не правку исходного кода.

2. **Код пишем по принципам SOLID, DRY и KISS.**
   - SOLID: у модуля и процедуры одна ответственность; зависимости — через программные интерфейсы, а не через детали реализации.
   - DRY: общая логика выносится в общие модули, без копирования кода.
   - KISS: выбираем самое простое решение, которое закрывает требование.

3. **Внешние источники указываем всегда.** Если используем информацию из интернета
   (документация, статьи, ИТС, форумы, репозитории), указываем ссылку на источник
   в ответе, а при переносе решения в код — в комментарии рядом с ним.

4. **Перед написанием кода прогоняем ТЗ через навыки superpowers.**
   Навыки установлены глобально в `~/.claude/skills/`
   (источник: https://github.com/obra/superpowers). Порядок работы:
   - `brainstorming` — разбор ТЗ, уточнение требований и проектирование решения;
   - `writing-plans` — пошаговый план реализации;
   - `executing-plans` / `subagent-driven-development` — реализация по плану;
   - `verification-before-completion` — проверка результата перед сдачей.
